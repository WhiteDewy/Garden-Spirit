# 星灵花园 · 前后端接入与 UI/UX 路线

## 当前落地

- `/garden` 作为首页唯一聚合入口：今日来信、继续上次、信任等级、待验证、灵魂碎片、记忆召回。
- `/recommended-spirits` 作为“今天想被谁接住”的推荐来源；首页显示第一位推荐，聊天页把 `persona` 传回 `/opening` 和 `/chat`。
- `/chat` 的 `lit_fragments / seen_fragments / actioned_fragments / keepsake_created` 转成即时成长反馈，不把后端结果藏在数据库里。
- `/mailbox/today`、`/person/{id}/letters`、`/person/{id}/journal` 保持信件和日记的双向入口。
- `/person/{id}/fragments`、`/person/{id}/findings` 继续作为“我的宇宙”的深度页面数据源。

## 页面职责

| 页面 | 主要数据 | 用户下一步 |
| --- | --- | --- |
| 花园 | `garden + opening + recommended-spirits` | 点星灵聊天、打开来信、继续昨天 |
| 聊天 | `chat` | 看到成长反馈，进入信箱/宇宙 |
| 信箱 | `mailbox/today + letters + journal` | 读信、写下此刻 |
| 我的宇宙 | `fragments + findings` | 进入星盘轮、验证判断 |
| 我的 | `person + fragments + recommended-spirits` | 查看关系与成长概览 |

## 统一视觉规则

1. 功能页使用“深林绿 + 月金 + 雾玻璃”作为共同底色；星盘轮的金/冰蓝/玫瑰色只作为星区语义色。
2. 所有页面使用同一组 4 项底部导航，红点只表示可处理状态：未读来信、待验证判断。
3. 首页负责“回家”和下一步行动，不展示完整数据表；解释链下沉到信箱、星盘轮和咨询页。
4. 后端结论不在前端重新计算。前端只做展示、排序（如首页 top 3）和状态反馈。

## 下一阶段

- 增加 `/personas` 或在推荐接口返回 `spirit_intro`，完成星灵选择半屏弹层。
- 将 `preferred_persona` 读写接入首页和聊天，换星灵后刷新 `/garden` 与 `/opening`。
- 扩展 `/garden` 的确定性今日星象字段（时间段、月相、月亮落座、行运提示），让花园天气从静态氛围变成真实状态。
- 为 `journal` 增加删除能力前，前端保持“可编辑/不可删除”的明确说明，避免做出假交互。
- 将推荐、首页聚合、聊天请求的加载/失败状态统一成轻量 toast + 页面内保留态，不因一次网络抖动清除本地身份。

## 验收指标

- 新用户从欢迎页到花园不超过一次主操作迷路。
- 老用户打开花园后 3 秒内能看到：今天的星灵、今日来信、一个明确下一步。
- 聊天回复后用户能看到至少一种可解释的变化反馈，且刷新页面后能在信箱/宇宙中找到对应结果。
- 页面之间切换时，底色、圆角、导航位置和按钮反馈保持一致。
