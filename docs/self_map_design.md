# 星灵花园 · 自我地图与陪伴设计（self_map_design）

> 状态：**设计草稿 v2，未开发**，待用户优化后进入实现。
> 覆盖：三系统分层架构 + 34 子类点亮系统 + 五层成长框架 + 陪伴协议 + 星灵人格签名表 + 来信式日记 + 咨询系统边界。

---

## 0. 背景与定位

**痛点**：咨询链路已通，但用户来闲聊时接不住。两种典型失败：
- **分享被怼回**——"今天看了天空之城的电影" → 返回一句转介话术，内容被无视。
- **情绪被处方化**——"今天心情不好" → 被推进完整占星管线，只想被听见却得到一次解盘。

**产品定性**：v2 定位是"自我探索**陪伴**"，哲学链 = 信任-占星-疗愈-无意识-有意识-陪伴-成长。
闲聊不是占星的附属边缘 case，而是**陪伴引擎**——与占星引擎并列的另一台引擎。

**参考对象**：林间聊愈室（MoodTalker）——通用心理陪伴 App。借鉴其机制（情绪感知/记忆回引/隔天来信），但占星是我们的差异化（护城河不变）。

## 1. 核心架构：三系统分层（完全解耦）

| 系统 | 本质 | 回答的问题 | 内容 |
|---|---|---|---|
| **人格层 · 10 星灵** | 谁来回应 | 谁在陪你聊 | 日月水金火木土天海冥，人格/声音 |
| **随聊记录层 · 34 子类** | 聊过什么 | 成长记录 | 3 星区 34 子类，收集话题 + 日记 |
| **咨询预测层 · 8 领域** | 能问什么 | 正儿八经占星 | 古典占星引擎，出结论 |

**边界规则（本轮定稿）**：
- **星灵选择与话题完全无关**：星灵选择 = **行运推荐 + 用户自选**，不因话题推荐星灵。每个星灵拥有完整 agent 能力，什么话题都能接。
- **34 子类只记录"你聊过什么"，不声称"你是谁"**：纯话题收集，星座区是话题的"原型风格"标签，不是给用户贴星座标签（保硬线）。
- **8 领域是独立预测系统**：古典占星、出结论，也写日记但是另一套，不参与 34 子类。
- 咨询轨道可**反向点亮** 34 子类（见 §5），这是差异化优势。

### 1.1 人格层 · 10 星灵（回归行星）

- 现有 10 个宝石人格（锆石/粉晶…）→ **回归/替换为 10 个行星灵**，人格声音嫁接移植。行星是内核，宝石是演化回退。
- 星灵选择机制：**行运推荐 + 用户自选**（完整方案稍后定，见 §11）。
- 每个星灵都有自己的讲话方式，以自己的方式站在整个 agent 基础上疗愈/链接/咨询用户。

**10 星灵签名表**——每颗星既是人格，也是"写给用户某部分自己的信"的落款：

| 星灵 | 疗愈名 · 签名 | 写给 | 它常对你说的话 |
|---|---|---|---|
| ☀ 太阳 | **想被看见的我** | 写给那个一直躲在别人光芒后面的自己 | 你值得被看见、被认可 |
| ☾ 月亮 | **想被抱抱的我** | 写给那个强撑了很久、总说"我没事"的自己 | 你可以累，可以靠过来 |
| ☿ 水星 | **想说话的我** | 写给那个话到嘴边又咽回去的自己 | 你说的值得被听见 |
| ♀ 金星 | **想爱与被爱的我** | 写给那个觉得自己不配被爱的自己 | 你本来就值得被爱 |
| ♂ 火星 | **想要就冲的我** | 写给那个犹豫不决、迟迟不敢开始的自己 | 你可以迈出那一步 |
| ♃ 木星 | **想飞的我** | 写给那个困在原地、忘了还可以去远方的自己 | 世界比你想的更大 |
| ♄ 土星 | **想负责的我** | 写给那个扛着太多、不敢放下的自己 | 你可以把一部分放下 |
| ♅ 天王星 | **想挣脱的我** | 写给那个困在"应该"里、快忘了自己是谁的自己 | 你可以不一样 |
| ♆ 海王星 | **想做梦的我** | 写给那个疲惫的现实主义者 | 允许自己有一片梦 |
| ♇ 冥王星 | **想深挖的我** | 写给那个假装没事、把伤藏得很深的自己 | 那些深的，值得被看见 |

**签名 = 谁在写（想要的部分），写给 = 谁在读（匮乏的部分）**——每封信都是用户心里两个部分之间的对话，是自我和解。

### 1.1.1 「写给」是动态的：星盘定底 × 语境定刻

**问题**：表里"写给"是固定的，读起来像"太阳星灵只陪躲在光芒后面的人"。可有的人天生就是小太阳（光芒万丈）——她不是那个躲光的人，照这张表她永远不是太阳星灵的收信人。这跟星座区"不贴标签"的硬线自相矛盾。

**三层解法**：

1. **签名是星灵说话时的自称，不是对用户的画像**。十颗星的签名合起来才是完整一个人内心的十个声音。小太阳不是没有「想被看见的我」，只是那一面已被照亮——**照亮 ≠ 声音消失，课题换了**。
2. **固定的是签名（星灵的声音），流动的是"写给"（此刻课题在行星光谱的哪一端）**。表里的"写给"是最普适的默认值；真系统里收信人由下面两层识别。
3. **识别 = 星盘定底 × 语境定刻**：
   - **星盘定底（Domain 出，硬线内）**：本命相位/落宫 → 每颗星的**长期课题端**，建盘时一次性算好，基本不变。小太阳（太阳合木/落狮子）→ 底="天生发光，但可能累了自己"；躲光的人（太阳刑土/落12宫）→ 底="怕被看见，不敢站进光里"。这不是 LLM 猜的，是 Domain 出的占星解读。
   - **语境定刻（意图层）**：此刻哪一面被激活。LLM 只报"哪颗星被触动 + 当下情绪/诉求 + 抓手（用户原话）"，**不判方向**。
   - **写给 = 底 × 刻**。小太阳今天聊"所有人都靠我撑着，我好累" → 太阳课题激活在"熄灯的一面" → 太阳信写给："你照亮了所有人，那谁来照亮你？你允许自己熄灭一下吗？"
4. **双端兜底（防贴错标签）**：语境含糊/置信度低时，信用双端写法邀请用户认领，不用单极判决。例——火星星灵："你有时是那个犹豫很久不敢动的人，有时是那个先冲了再说的——今天，你是哪一种？"

**实现落地（Phase 1 扩展）**：LLM 意图调用除 `soul_fragments`（34 子类点亮）外，再输出 `planet_activation`（哪颗星被触动 + 当下情绪/诉求）——**只报激活，不判方向**。方向由 Domain 的相位表给（硬线）。

### 2.4 点亮机制：多维多亮

- **一条消息可同时点亮多个子类**（多标签，不做最强透镜去重）。
- 示例：用户说"今天被老板骂了，好生气，想辞职去旅行" →
  - 行星：火星·行动引擎（愤怒）+ 木星·信念高塔（旅行）
  - 宫位：10宫·事业高塔（老板）+ 9宫·远方灯塔（旅行）
  - 星座：射手·自由之箭（想逃离束缚）
- **星座区 = 话题的"原型风格"**：点亮射手是"今天的话题有射手式追求自由的质地"，不是"你是射手座"。系统只记录话题属性，不声称用户属性。

### 2.5 结算与视觉成长

- **每日结算**：白天累积，晚上/次日来信时出"今日灵魂碎片"卡（避免每条消息都亮、点亮贬值）。每天封顶展示 top 3。
- **Icon + 数字**：数字 = 该维度探索深度；达阈值 Icon 升级（如火星从小火苗 → 燃烧的火炬）。
- 数字语义 = **深度分**（见 §4.2），不是纯次数。

### 2.6 行运层（时间层，非第 13 板块）

- 每日/每月行运走到哪个宫，哪个扇区当天微微亮起——"今天你的『事业高塔』被触动了"。
- 呼应首页 3 星灵轮换 + 每日来信。

## 4. 五层成长框架（解决"点完了没意思"）

34 点亮只是广度第一层，真正的游戏有五层，**永远点不完**：

| 层 | 内容 | 会不会"完" |
|---|---|---|
| 广度 | 34 子类点亮（收集） | 会点完（这是收集层） |
| 深度 | 每格升阶 1-5 级 | 很难点满（真实成长信号才升级） |
| 组合 | 星×宫×星座交叉 | 广度点满才开始出现（模式级洞察） |
| 报告 | 周/月成长报告 | 数据越全，报告越准，越有意思 |
| 活态 | 行运每天移动 + 盲区 | 永远在变，永远有没亮的 |

### 4.1 盲区即课题（关键 reframe）

**未点亮的角落，本身就是内容。** 用户用了半年"我的深海"一直没亮 → 这是照见：

> "你聊了很多工作、很多关系，但『隐秘花园』——梦境、独处、灵性——你一次都没碰过。**你不碰的角落，往往是你最需要面对的。**"

占星"空宫不空"的疗愈版。点亮 ≠ 通关；全亮 ≠ 结束。叙事定位："认识自己是一生的功课"（哲学链终点），而非"收集 34 张卡通关"。

### 4.2 深度分体系（升阶不靠次数）

| 动作 | 深度分 |
|---|---|
| 提及 | +1 |
| 倾诉 | +3 |
| **被照见**（用户说"对，就是这样"） | +5 |
| **完整咨询反向点亮** | +10 |
| **触发行动**（聊完去做了一件事） | +20 |

接现有 `confirmed/refuted` 反馈系统：用户确认的那一刻，才算"真点亮"。

### 4.3 格子反转机制（点满的格子找你说话）

收集到一定程度，机制反转——不是你去点亮，是格子来找你：
- "你已经有 20 次聊到月亮了，要不要看看它为什么对你这么重要？"（触发一次月亮星灵深聊）
- 全亮的格子变成"活着的格"，持续发起新对话方向。
- 收集系统从"打卡"变成"关系"——格子在主动认识你，呼应"越聊越懂你"。

## 5. 反向点亮（差异化优势）

- **完整咨询可反向点亮 34 子类**：一次触及灵魂的完整咨询 = 一次深度照见，比十次闲聊的随手点亮更值钱，给最高深度分（+10）。
- 这是林间给不了的：林间只能靠闲聊收集，我们能靠专业咨询点亮，而且点得更深。
- 随聊只记录到 34 子类；咨询只写咨询记录 + 反向点亮 34 子类（见 §6 日记双存）。

## 6. 日记：前端统一，后端两套

- **用户看到**：一个日记页面（都是"我的日记"）。
- **后端存储**：两套独立系统——
  - 随聊成长记录（34 子类收集 + 成长日记）
  - 咨询记录（8 领域结论 + 咨询日记）
- 后端分开存，前端统一呈现。

### 6.1 来信式日记（随聊成长记录）

- **正文 = 那段对话本身，不是它的压缩版**：当一次随聊产生"值得记住的时刻"，星灵那段完整回复原样成为当天的日记条目（keepsake）。治愈感来自**具体**，不来自总结——用户被感动的是那句话，不是它的摘要。
- **灵魂碎片点亮 = 数据卡（脚注），不是正文**："今日灵魂碎片"作为附属小卡片贴在日记下方，主体永远是星灵那段完整的话。
- **星灵来信用疗愈名落款**：每颗星的来信用自己的疗愈名签名——月亮星灵 →「想被抱抱的我」。收信人读到的是"我自己的一部分写给其余的我"。

**示例（月亮星灵来信）：**
```
2026-08-07 · 月亮星灵 ·「想被抱抱的我」
────────────────────────────
你看的三部电影，像三座天气不同的城。
……（星灵完整回复正文，具体回应每部电影，逐一接住）
你月亮落在向往梦的位置，你是个需要梦来托底的人。
────────────────────────────
◈ 今日灵魂碎片：海王星·梦境迷雾 / 金星·爱与审美
  双鱼·梦幻之海 / 火星·行动引擎

                        —— 想被抱抱的我
```

### 6.2 落款是怎么来的：内容 → 情绪需求 → 疗愈名（推导链）

落款不是拍脑袋选的，也不是"聊了什么话题就亮哪颗星"——是识别内容背后的**情绪需求**，映射到对应的疗愈名。以上面示例为例：

| 你聊的内容 | 信号 |
|---|---|
| 天空之城 · 荒凉的遗址 | 喜欢"曾经辉煌如今空寂"的废墟 → 心里有一片荒地（苍凉共鸣） |
| 芙莉莲 · 很治愈 | 在找"能被温柔接住"的东西 → 最近需要被治愈 |
| 坠落 · 惊心动魄、很解压 | 解压 = 有东西压着需要出口 → 高张力在释放日常紧绷 |

三条信号汇成一个主需求：**最近有点重、有点孤独，在找能被温柔抱一下的东西** → 月亮星灵 ·「想被抱抱的我」。

**判别规则**：
- **主信号 → 落款星灵**：最强情绪需求定落款。海王星也在边上（芙莉莲很梦幻），但主线是"治愈 / 被接住"而非"做梦"，主需求落月亮。
- **次信号 → 灵魂碎片**：梦幻这条线没有浪费，掉进当日灵魂碎片（海王星·梦境迷雾 / 双鱼·梦幻之海）——正是上面示例脚注里的内容。

> **实现要求**：推导链必须**显式可解释**——LLM 输出情绪需求（主 / 次），映射规则决定落款与灵魂碎片。不能是黑箱，否则"落款"就成了玄学。

## 7. 陪伴协议（随聊轨道怎么"接住"）

### 7.0 根原则：治愈感来自"具体"，不来自"总结"

- 回应永远针对用户的具体内容，永不落入通用模板。**模板就是"怼回"（最初的痛点），具体才是"接住"**——用户说"看了天空之城"，星灵就要真正接住那部电影，而不是回一句"哇，电影不错呢"。
- 星灵回应的每一句，都要能让用户感到"**他在认真看我说的话**"。
- 这条原则同时约束日记（正文保留完整对话，见 §6.1）与陪伴协议每一步。

### 7.1 意图模型（借鉴 MoodTalker，内核不同）

按 **情绪状态 × 诉求类型** 判断，而非按领域分类：
- 诉求类型：被听见 heard / 被安慰 soothed / 被梳理 sorted / 被推动 pushed。

### 7.2 陪伴五步协议

1. **感知**：识别情绪状态 + 诉求类型。
2. **接住**：共情确认、命名情绪——"嗯，我听见了。今天不太顺，是吗？"
3. **镜映**：内容回映 + 记忆回引（"你上周也说睡不好，我记着呢"）。
4. **递出口**：给选择——继续聊，或"想看看你盘上这颗星怎么说？"（信任门槛达标才给）。
5. **护城河接入**：只有走到第 4 步，才调 Domain 出真实星盘结论。LLM 无权在陪伴里自创占星说法。

### 7.3 软牵引门控（何时递盘）

**占星只在"行动导向"诉求下递，绝不在"接受导向"诉求下递。**

| 诉求类型 | 递盘合适吗 | 软牵引方式 |
|---|---|---|
| 被听见 heard | ✗ 递盘=没听见你 | 不给盘，继续陪 |
| 被安慰 soothed | ✗ 先接住，盘后置 | 情绪平复后才可轻轻一句 |
| 被梳理 sorted | ✓ 最佳窗口 | "你这一团乱，盘上可能有条线——想不想看看？" |
| 被推动 pushed | ✓ 天然下一步 | "你的土星在告诉你什么时候该发力——要我讲讲吗？" |

**软牵引 = 诉求类型门控 × 共振星灵 × Domain 落点**。

### 7.4 安全护栏

- 陪伴轨道识别到深水区（反复坠落/绝望/自伤意象）→ 不硬接，走现有 safety gate 转介专业支持。

## 8. 模式系统（5 模式）

| 模式 | 特质 | 轨道 |
|---|---|---|
| **随心聊** | 默认态。接住一切，你先说；契合 34 子类收集 | 陪伴 |
| **快速咨询** | 一件事，要个说法 | 咨询 |
| **深度咨询** | 一个领域想聊透（疗愈五步） | 咨询 |
| **年度主题** | 这一年怎么过 | 咨询 |
| **月度主题** | 这个月/近期怎么过 | 咨询 |

- **情绪疗愈合并进随心聊**：用户说"今天心情不好" → 意图层检测 `Vent + 诉求=被安慰` → 随心聊内部走情绪接住子状态。
- **三级优先**：① 用户显式选模式 → 按模式引导；② 系统识别咨询意图 → 滑进对应模式；③ 兜底 → 先走陪伴（宁可多接一句，也不处方化）。
- 前端显示模式，用户可主动切换；默认随心聊。

## 10. 借鉴 MoodTalker：什么照搬、什么升级

| MoodTalker 机制 | 借鉴 | 我们的升级 |
|---|---|---|
| 情绪感知优先 | 照搬进陪伴五步第 1 步 | 感知后接占星镜映 |
| 记忆主动回引（反复提及） | 照搬进第 3 步镜映 | 回引 + 点亮 34 子类 |
| 隔天来信 | 照搬进节奏设计 | 来信带"今日灵魂碎片 + 哪个角落被触动" |
| 六大板块图鉴 | 不照搬分类 | 用 3 星区 34 子类当骨架（占星原生） |
| 通用小动物陪伴 | — | 行星原型人格：陪伴本身就是占星 |

**差异本质**：MoodTalker 是"通用陪伴"，任何 LLM 壳可复刻；我们是"接住情绪 + 用占星当底色镜映"，占星长在陪伴里。

## 12. 设计硬线（不可违反）

- **占星结论全由 Domain 出**，LLM 自由度只在"怎么疗愈 / 怎么陪伴"。
- 34 子类只记录话题，不声称用户属性（星座区 = 话题风格，不贴标签）。
- 陪伴叙事默认不引用星盘；要碰盘必须由 Domain 出事实。
- 星盘不是判决书，是一张地图；绝不输出"命好坏/一定离婚"。
