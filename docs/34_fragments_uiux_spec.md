# 随聊轨道 · 34 子类点亮系统 —— 前端 UI/UX 设计依据

> 用途：给前端 UI/UX 敲定界面用。一份把「设计稿 + 已实现代码 + 前端接口契约」对齐的清单。
> 来源：`docs/self_map_design.md` §2（设计）、`application/conversation/fragments.py`（实现）、`application/api/main.py`（契约）。
> 状态标注：✅ 已实现 / 🔶 已设计未实现（见 §9 状态清单）。

---

## 1. 一句话定位（先给设计师的定调）

**34 子类点亮系统 = 随聊轨道的"自我星盘轮"。** 用户聊过什么，轮盘上的格子就点亮什么；点亮 = 记录"聊过什么"，**不是**给用户贴性格/星座标签。

产品叙事落点：**「认识自己是一生的功课」**，不是「收集 34 张卡通关」。未点亮的格子（盲区）本身也是内容（§6）。

## 3. 点亮机制（数据是怎么来的，前端怎么消费）

### 3.1 多维多亮
一条消息**可同时点亮多个格子**（最多 6 个，`MAX_FRAGMENTS=6`），不做"最强透镜去重"。

例：用户说"今天被老板骂了，好生气，想辞职去旅行" →
- 行星：`mars_action`（愤怒）+ `jupiter_faith`（旅行）
- 宫位：`house10_career`（老板）+ `house9_far`（旅行）
- 星座：`sagittarius_arrow`（想逃离束缚）

### 3.2 分类器
LLM 受控枚举分类（只能从 34 个 id 里选，不能发明），**LLM 不可用/失败 → 关键词规则兜底**。纯随聊轨道点亮；咨询轨道当前不点亮（反向点亮见 §8）。

### 3.3 深度分（数字 = 探索深度，不是次数）
| 动作 | 深度分 | 实现状态 |
|---|---|---|
| 提及（普通聊到） | +1 | ✅ |
| 倾诉（负面情绪消息） | +3 | ✅（`needs_care` 判定） |
| 被照见（用户确认"对，就是这样"） | +5 | 🔶 设计已定，未实现 |
| 完整咨询反向点亮 | +10 | 🔶 Phase 1 剩余 |
| 触发行动（聊完去做了一件事） | +20 | 🔶 设计已定，未实现 |

### 3.4 前端拿到的实时数据
`POST /chat` 每轮响应带回点亮结果（随聊轨道）：
```json
{
  "answer": "...",
  "emotion": "low",            // 情绪感知：calm/happy/low/anxious/angry/tired/lonely/confused/pressured/fearful
  "request_type": "soothed",   // 诉求：heard/soothed/sorted/pushed
  "trust_level": "acquaintance", // stranger/acquaintance/trusted/intimate
  "lit_fragments": ["moon_tide", "house4_home"],  // 本条点亮了哪些子类
  "intent_domain": "emotion", "mode": "deep", "written_back": false
}
```

**UI 决策点**：`lit_fragments` 是实时的；但设计（§2.5）要求**每日结算**、每天封顶展示 top 3，避免"每条都亮、点亮贬值"。所以 UI 需要两种形态并存：
- 聊天过程中的**轻反馈**（格子微闪 / 聊天气泡下方一行小字"今天聊到了：月亮·情绪潮汐、4宫·心灵小屋"）——克制，不打断。
- 每日来信/日记里的**「今日灵魂碎片」卡**（正式结算，见 §5）。

## 4. 视觉成长（格子怎么"活"）

### 4.1 Icon + 数字
每个格子 = **Icon + 深度分数字**。数字 = 该维度探索深度；**达阈值 Icon 升级**（例：火星从"小火苗"→"燃烧的火炬"）。

### 4.2 升阶与"级"
设计（§4.2）定义五层成长框架的深度层为 **1-5 级**；但**当前后端只存连续深度分（int），没有"级"字段**。

**UI 决策点**：前端可以从深度分自己推级（如 1/3/10/30/100 五档），或者要求后端补 `level` 字段。推级阈值需要产品敲定。Icon 升级动画（升阶反馈）是这个系统的"爽点"，值得做足。

### 4.3 三种视觉状态
| 状态 | 判定（深度分） | 视觉 |
|---|---|---|
| 未点亮（盲区） | `depth == 0` | 暗格 / 剪影，明确可辨 |
| 已点亮 | `depth > 0` | 亮起 + 深度数字 |
| 已升阶 | 达档位阈值 | Icon 换形态 + 升级动画 |

> 盲区（未点亮）要**足够醒目**——它承载 §6 的核心叙事，不是"没玩到的地方"。

## 5. 每日结算 · 「今日灵魂碎片」卡

- 白天随聊累积点亮，**晚上/次日来信时**出"今日灵魂碎片"卡。
- 每天封顶展示 **top 3**（按深度分）。
- 数据现状：`lit_fragments` 每轮有，但**没有"按天聚合 top3"的后端端点**——🔶 未实现，前端需配合（可让后端加 `GET /person/{id}/fragments/today`，或前端本地按日聚合）。

**卡片样式参考**（来自设计稿 §6.1 示例，附在来信/日记底部）：
```
◈ 今日灵魂碎片：海王星·梦境迷雾 / 金星·爱与审美
  双鱼·梦幻之海 / 火星·行动引擎
```

## 6. 与日记、来信的关系（随聊记录层的完整闭环）

前端**一个日记页面**，后端两套存储（随聊成长记录 + 咨询记录），统一呈现。随聊这半套：
- **来信式日记**：正文 = 星灵那段完整回复原样（keepsake），不是压缩版；"灵魂碎片"是**脚注小卡**，不是正文。治愈感来自具体。
- **星灵落款**：每颗星的来信用自己的疗愈名签名（如月亮星灵 →「想被抱抱的我」）。🔶 落款机制 Phase 1 剩余。
- 已实现：`POST /journal`、`GET /person/{id}/journal`、`POST /mailbox/today`（每日来信）、`GET /person/{id}/letters`。

**UI 层级建议**：首页入口 →（今日来信 / 自我星盘轮 / 日记）。星盘轮是"随聊记录层"的图鉴页；来信是"每日结算"的载体。

## 7. 盲区即课题（未点亮格子的叙事，UI 文案要接住）

占星"空宫不空"的疗愈版。用户聊了半年，某个角落（如 `house12_secret` 隐秘花园）始终没亮 → 这是照见：

> "你聊了很多工作、很多关系，但『隐秘花园』——梦境、独处、灵性——你一次都没碰过。**你不碰的角落，往往是你最需要面对的。**"

**UI 文案约束**：
- 点亮 ≠ 通关，全亮 ≠ 结束。
- 空格子不是"收集进度条上的空槽"，是"认识自己的盲区"。
- 盲区可触发「格子反转」（§8），也可以是周报/月报里的叙事素材。

## 8. 已设计、对 UI 有要求但未实现的部分（设计时留位）

| 机制 | 设计出处 | 对 UI 的要求 |
|---|---|---|
| **格子反转** | §4.3 | 点满/高亮的格子会"反过来找你说话"（如"你已 20 次聊到月亮，要不要看看它为什么对你这么重要"）。UI 要支持"格子主动发起深聊"的入口。 |
| **行运层微亮** | §2.6 | 每日/每月行运走到哪个宫，哪个扇区当天"微微亮起"（非点亮，是氛围）。首页呼应 3 星灵轮换。 |
| **五层成长** | §4 | 广度（34 点亮）→ 深度（每格 1-5 级）→ 组合（星×宫×星座交叉）→ 报告（周/月）→ 活态（行运+盲区）。UI 按"点不完"设计，不是 34 格通关。 |
| **咨询反向点亮** | §5 | 一次完整咨询 = 深度照见，反向点亮 34 子类（+10）。咨询后格子该有"被深度点亮"的反馈。🔶 Phase 1 剩余。 |
| **星球激活** | §1.1.1 | `planet_activation`（哪颗星被触动 + 当下情绪/诉求）并入意图 LLM。与点亮并列的"情感共振"信号。🔶 Phase 1 剩余。 |
| **被照见 +5 / 触发行动 +20** | §4.2 | 接 `confirmed/refuted` 反馈系统。"用户确认的那一刻，才算真点亮"——UI 的确认交互（如"对，就是这样"按钮）会推动深度分。 |

## 10. 设计硬线（UI 文案绝不能越线）

1. **34 子类只记录"你聊过什么"，不声称"你是谁"。** 星座区 = 话题的"原型风格"标签，不是"你是射手座"。UI 文案一律用**"今天聊到了火星式的冲动"**，禁用**"你是一个行动力很强的人"**。
2. **陪伴 ≠ 解盘。** 随聊轨道（陪伴协议）的回复禁止任何占星结论；UI 不要把随聊回复包装成"星盘解读"。
3. **占星结论全由 Domain 出。** LLM 自由度只在"怎么疗愈/怎么陪伴"。UI 上"想看盘"的入口由软牵引门控决定（诉求=被梳理/被推动 且 信任达标才出现），不是常驻按钮。
4. **星盘不是判决书，是一张地图。** 不出现"命好/命坏/一定分手"式文案。

## 11. 前端接口契约速查（全量）

| 端点 | 用途 | 关键字段 |
|---|---|---|
| `GET /person/{id}/fragments` | 自我星盘轮全量 | `fragments:[{id, zone, name, triggers, depth}]`（zone ∈ planet/house/sign） |
| `POST /chat` | 对话 | 入参 `{person_id, session_id, message, persona, mode}`；出参含 `emotion/request_type/trust_level/lit_fragments` |
| `POST /journal` / `GET /person/{id}/journal` | 日记 | `{content, mood}` → `{id, content, mood, ai_summary, created_at}` |
| `POST /mailbox/today` | 今日来信 | `{person_id}` → `LetterOut{sender_zh, title, body, kind}` |
| `GET /person/{id}/letters` | 来信列表 | `LetterOut[]` |
| `GET /garden` | 首页聚合 | `{today, letter, continue_from, domains, trust_level}` |
| `GET /person/{id}/profile` | "我的宇宙"（咨询层） | `domain_summaries / verified_findings / key_dates / trust_level` |

> 首页布局建议（设计稿 §3）：列表式三大板块——**行星动力（10）/ 宫位舞台（12）/ 星座风格（12）**，可折叠或点进二级页。三大板块同时是"自我星盘轮"的入口。

## 12. 需要产品/用户先敲定的 UI 决策点（本稿的开放问题）

1. **深度分 → 级数**：前端自己推 1-5 级，还是后端加 `level` 字段？（决定 Icon 升级逻辑放哪）
2. **实时点亮 vs 每日结算**：聊天过程里点亮反馈做到多重？每日"今日灵魂碎片"卡（top3）需要后端聚合端点还是前端本地聚合？
3. **轮盘布局**：圆形星盘轮（占星感强，34 格拥挤）还是三区列表/九宫格（清晰）？混合（首页列表、详情页圆轮）？
4. **行运微亮**：Phase 1 是否排期？它影响首页氛围光效。
5. **盲区叙事落点**：盲区提示出现在哪——轮盘空态、周报、还是格子反转主动触发？
