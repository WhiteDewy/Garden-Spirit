# 星灵花园 · 前端 IA / UIUX V7 高阶规划

> 状态：**设计方向定稿，待分阶段实现**（2026-08-17）  
> 背景：现有首页视觉气质已成立，但信息密度过高，星灵、来信、天气、碎片、日期、关系等级、行运解释同时争夺注意力。V7 不再继续给首页加模块，而是重排信息架构，让首页成为“遇见星灵”的入口。  
> 配套：`docs/frontend_ui_conventions.md` · `docs/homepage_design.md` · `docs/frontend_visual_refactor_spec.md` · `docs/frontend_backend_integration_plan.md`

---

## 0. 一句话结论

**星灵花园不是占星 Dashboard，而是一个可以回来的陪伴空间。**

首页只回答一个问题：

> **今天，谁来陪我？**

其他信息不是删除，而是回到更合适的位置：

- 来信 / 行运 / 今日碎片 → **信箱**
- 星盘 / 证据链 / 自我碎片 / 待验证判断 → **宇宙**
- 星灵偏好 / 关系成长 / 隐私设置 → **我的**
- 真实陪伴与占星问答 → **聊天**

## 1. 设计原则

### 1.1 从 Dashboard 转向 Encounter

旧首页逻辑：

> 告诉用户今天有什么。

V7 首页逻辑：

> 让用户遇见今天陪自己的星灵。

这两个方向对应完全不同的产品气质：

| 方向 | 结果 |
|---|---|
| 信息聚合 Dashboard | 漂亮但拥挤，用户像在看功能卡片 |
| 星灵 Encounter | 留白、有主角、有生命感，用户想点它说话 |

### 1.2 首页必须只保留一条主叙事

首页只留下 5 层：

1. **天空 / 光线**：表达时间、昼夜、情绪氛围。
2. **星灵立绘**：唯一视觉核心。
3. **疗愈名**：如“想飞的我”。
4. **一句话**：如“往远处看看，路比你以为的宽。”
5. **一个 CTA**：和它聊聊 →

首屏不再展示：

- 欢迎来到花园
- 今天的你怎么样
- 夜晚 · 花园天气
- 初遇 · 陌生
- Inner Weather 卡片
- 今日来信卡片
- 今日碎片卡片
- 为什么是它按钮
- 长段 opening 文案
- 大量解释性装饰文字

### 1.3 内容不减少，只做渐进展开

V7 的核心不是“少做功能”，而是“晚一点出现”。

| 内容 | V6 常见位置 | V7 位置 |
|---|---|---|
| 为什么是这个星灵 | 首页按钮 | 点击星灵 / 半屏 Sheet / 信箱解释链 |
| 今日来信 | 首页卡片 | 信箱首位 |
| 行运提醒 | 首页卡片 | 信箱“今日星象来信” |
| 今日碎片 | 首页卡片 | 信箱脚注 + 宇宙微亮 |
| 关系状态 | 首页标签 | 星灵靠近动画 / 我的关系页 |
| 星盘信息 | 首页解释 | 宇宙 / 星盘咨询 |
| 天气 | 首页文字 | 全局光线系统，不做独立主模块 |

## 2. 产品信息架构

底部导航保留四项：

```text
花园      信箱      宇宙      我的
Garden   Mailbox   Cosmos    Me
```

### 2.1 花园 Garden

职责：**每日回家与遇见星灵。**

只负责：

- 今天的天空 / 光线 / 时间感
- 今天陪你的星灵
- 星灵疗愈名
- 一句今日星语
- 进入聊天
- 底部导航红点

不负责：

- 来信正文
- 行运细节
- 解释链
- 今日碎片列表
- 个人画像
- 关系状态说明

### 2.2 信箱 Mailbox

职责：**所有“今天递到你手里的东西”。**

包括：

- 今日来信
- 太阳 / 月亮 / 木星等星灵来信
- 行运提醒 / 今日星象来信
- 星灵留言
- keepsake 来信式日记
- 今日碎片脚注
- 用户自己写下的日记
- 来信落款推导链

建议内部结构：

```text
信箱
  ├─ 今日
  │   ├─ 今日来信
  │   ├─ 今日星象来信 / 行运提醒
  │   └─ 今日灵魂碎片脚注
  ├─ 来信
  │   ├─ 星灵来信
  │   ├─ keepsake
  │   └─ 为什么是这颗星落款
  └─ 手账
      ├─ 我写下的日记
      └─ 写下此刻
```

命名要求：底部导航叫“信箱”，页面标题也应叫“信箱”，不再用“日记”作为一级标题。

### 2.3 宇宙 Cosmos

职责：**所有“我是谁 / 星盘如何理解我”的结构化地图。**

包括：

- 自我星盘轮
- 34 子类碎片
- 行星 / 宫位 / 星座结构
- 星盘咨询
- 待验证判断
- 证据链
- 行运微亮
- 成长报告 / 时间河（后续）

宇宙允许信息密度更高，因为用户进入这里的意图是“理解”。但首页不能承担这个任务。

### 2.4 我的 Me

职责：**关系、偏好、身份与控制权。**

包括：

- 个人资料
- 我的常驻星灵 / preferred_persona
- 10 星灵图鉴
- 星灵关系成长
- 记录天数 / 点亮碎片 / 沉淀判断
- 隐私与安全
- 推送设置
- 数据导出 / 删除入口

### 2.5 聊天 Chat

职责：**核心陪伴循环。**

聊天不是一级 tab，因为它是从“星灵”触发的行为。入口来自：

- 首页星灵
- 信箱来信
- 宇宙咨询
- 继续昨天
- 某个碎片详情

## 3. 首页 V7 规格

### 3.1 目标画面

```text
┌─────────────────────────┐
│ GARDEN SPIRIT        ○  │
│                         │
│                         │
│          08 · 16        │
│                         │
│              ☾          │
│                         │
│          ✦              │
│       [ 星灵立绘 ]       │
│                         │
│        想飞的我          │
│  往远处看看，路比你以为的宽。 │
│                         │
│       和它聊聊 →         │
│                         │
│                         │
│ 花园     信箱     宇宙    我的 │
└─────────────────────────┘
```

### 3.2 首屏保留

- 极弱品牌名：GARDEN SPIRIT
- 极弱日期：08 · 16
- 天空 / 昼夜光线
- 星灵立绘
- 疗愈名
- 一句今日星语
- 单一 CTA：和它聊聊 →
- 底部导航

### 3.3 首屏移除

- 产品欢迎语
- 多段 opening
- 星灵长介绍
- 为什么是它按钮
- Inner Weather / 今日来信卡
- 今日碎片卡
- 信任等级文本标签
- 花园天气文本
- 多 CTA 并列

### 3.4 隐藏交互

点击星灵或光晕时出现半屏 Sheet：

```text
为什么今天它来找你？

今天这束光来自木星。
它提醒你的不是“必须变好”，
而是：你可以把眼光放远一点。

[和它聊聊]   [收起]
```

Sheet 内容来自：

- recommended spirit reason
- recall lens
- 今日行运摘要
- 若无数据，降级成温柔文案

### 3.5 主星灵身份规则

首页中央星灵需要区分两种身份：

| 用户状态 | 首页中央显示 | 今日推荐如何出现 |
|---|---|---|
| 没有 preferred_persona | 今日推荐 top1 | 作为“今天先醒来的星灵” |
| 已有 preferred_persona | 用户常驻星灵 | 今日推荐只影响今日语气 / 来信 / Sheet 解释 |

这样用户会感觉：

> 这是我的星灵今天来看我。

而不是：

> 系统今天随机推荐了一个人格。

## 4. 页面级设计建议

### 4.1 欢迎页

定位：品牌序章。  
保留仪式感，但避免每次重复长序章。

建议：

- 首次可长，第二次必须跳过。
- CTA 保持唯一：“遇见我的星灵”。
- 不要在欢迎页解释全部功能。
- 欢迎页讲“世界观”，不是讲“功能列表”。

### 4.2 建档页

定位：让星灵认识你。  
现有分步方式合理，继续保持。

建议：

- 建档不是表单，而是“星图正在形成”。
- 出生日期 / 时间 / 地点的输入说明保持简洁。
- 技术性解释留在帮助浮层，不占主流程。

### 4.3 Awakening 页

定位：星灵第一次醒来。  
这是从“填资料”到“进入花园”的仪式桥。

建议：

- 展示星图生成、第一颗星灵出现。
- 不要放太多功能入口。
- CTA 两个以内：进入花园 / 先说句话。

### 4.4 信箱页

定位：今日递来的信。  
从“日记”重命名为“信箱”。

视觉语言：

- 纸张
- 信封
- 落款
- 脚注
- 星尘便签
- 半透明奶白纸页

信息层级：

1. 今日来信
2. 今日星象来信 / 行运提醒
3. keepsake
4. 今日灵魂碎片脚注
5. 我写下的日记
6. 推导链折叠

### 4.5 宇宙页

定位：内在地图枢纽。  
现有“自我星盘轮 + 星盘咨询”双入口方向成立。

建议升级：

- 待验证判断做成小型“望远镜 / 待确认星点”。
- 今日行运微亮可以在宇宙页体现，不放首页。
- 星盘咨询继续强调“带着星盘看生活问题”，不要变成报告列表。

### 4.6 我的页

定位：关系档案与控制台。  
不要只是设置页。

建议新增：

- 我的常驻星灵
- 星灵偏好切换
- 关系成长记录
- 隐私与数据控制
- 推送开关

10 星灵列表可从“今日推荐”升级为“我的星灵图鉴”。

## 5. 天气 / 今日运势 / 星灵介绍的归位

### 5.1 天气

不建议做独立一级天气页。  
天气应该成为全局“光线系统”：

| 时间 | 视觉 |
|---|---|
| 清晨 | 雾白、浅青、露水绿 |
| 中午 | 奶油黄、晴空蓝、草绿 |
| 黄昏 | 杏色、灰粉、淡紫 |
| 夜晚 | 蓝灰、蓝绿、月金 |

前端只展示光线和空气感，不在首页写“花园天气”。

### 5.2 今日运势

不建议叫“运势”。  
推荐命名：

- 今日星象来信
- 今日光线
- 今日星语
- 今天的星象提醒

位置：信箱“今日”区。  
首页只用它生成一句短星语，不展示完整解释。

### 5.3 行运信箱

可以作为信箱的核心功能，而不是独立 tab。

形态：

```text
今日星象来信

☉ 太阳提醒
今天你可能更想被看见。

☽ 月亮提醒
情绪需要一点空间。

♃ 木星提醒
有件事值得你大胆一点。
```

### 5.4 星灵介绍

不建议放首页。  
位置：

- 我的 / 我的星灵
- 点击星灵后的 Sheet
- 星灵选择半屏弹层

介绍字段：

- 星灵名
- 疗愈名
- 写给谁
- 适合什么时候找它
- 常对你说什么
- 与你当前状态的推荐理由

## 6. 视觉系统收口

### 6.1 四种材质

| 材质 | 用途 |
|---|---|
| 天空 / 光线 | 首页、全局氛围 |
| 纸张 / 信封 | 信箱、日记、keepsake |
| 星图 / 水晶 / 轨道 | 宇宙、星盘轮、证据链 |
| 星灵 / 光晕 / 呼吸 | 首页、聊天、我的星灵 |

### 6.2 卡片使用原则

首页：**尽量不用卡片**。  
信箱：可以用纸页卡。  
宇宙：可以用结构卡。  
我的：可以用档案卡。  
聊天：尽量少系统卡，用轻反馈。

### 6.3 动效原则

- 首页动效慢：呼吸、漂浮、星尘。
- 信箱动效轻：展开、翻页、信封浮现。
- 宇宙动效有结构：点亮、环绕、微亮。
- 聊天动效短：发送、回应、成长反馈。

必须支持减少动效模式，避免过度干扰。

## 8. 实施优先级

### P0：IA 与首页减法

- 首页保持 V7 极简。
- 删除或隐藏首页多余卡片。
- “为什么是它”移入星灵 Sheet。
- 信箱标题从“日记”改为“信箱”。
- 今日来信 / 今日碎片 / 行运全部归入信箱。

### P1：星灵身份统一

- 接入 preferred_persona。
- 首页、聊天、信箱落款共享星灵身份规则。
- 我的页补“我的常驻星灵”。
- recommended spirit 从“替代主角”改成“今日语境”。

### P2：组件拆分

拆 `pages/index/index.vue`：

```text
pages/index/index.vue
  ├── WelcomeStage.vue
  ├── RegisterStage.vue
  ├── AwakeningStage.vue
  └── GardenHome.vue
```

目标：避免 onboarding 样式污染首页。

### P3：信箱升级

- 今日 / 来信 / 手账 三段结构。
- 行运信箱接入。
- keepsake 与推导链视觉升级。
- 今日碎片作为脚注和轻入口。

### P4：宇宙与我的升级

- 宇宙加待验证入口。
- 行运微亮进入宇宙。
- 我的页补星灵关系 / 隐私 / 推送。
- 10 星灵图鉴从静态列表升级为可选择偏好。

## 9. 验收标准

首页：

- 老用户 3 秒内只看到一个主角：星灵。
- 首屏只有一个主要 CTA。
- 没有信息卡片堆叠。
- 不读长文也知道下一步是聊天。

信箱：

- 用户能明确理解这里收纳所有“给我的信”。
- 今日来信、keepsake、日记、解释链层级清楚。
- 首页红点与信箱未读状态一致。

宇宙：

- 用户知道这里是“理解我”的地方。
- 星盘轮、咨询、待验证不是互相抢入口。
- 占星证据链只在宇宙 / 咨询 / 信箱解释链中出现。

我的：

- 用户能找到星灵偏好、个人资料、隐私控制。
- 关系成长不是首页标签，而是可回看的长期记录。

全站：

- 页面之间不是同一种玻璃卡片换标题，而是各有材质：天空、纸张、星图、关系档案。
- 所有占星结论继续来自后端 Domain。
- 前端不硬编码占星判断。

## 10. 最终判断

V7 的关键不是继续做更多功能，而是敢于留白。

首页越少，星灵越像活的；  
信箱越集中，内容越有仪式感；  
宇宙越结构化，占星能力越可信；  
我的越清楚，用户越有安全感和控制权。

**下一版不要继续微调首页，而应按 P0 做一次“首页减法 + 信箱归位 + 星灵身份统一”的基础重构。**
