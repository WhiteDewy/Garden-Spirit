# Garden-Spirit V1 产品契约：月灵、低打扰闭环与记忆资产

> 生成日期：2026-08-20  
> 用途：在技术线继续推进 V8 主题观星台 / Intent / ReportRequest 时，冻结 V1 产品线口径，避免并行开发互相打架。  
> 范围：只定义产品行为、叙事规则、前端展示原则和验收标准；不替代 `domain_engine_v2.md`、`frontend_ia_uiux_v8.md` 的占星判断链技术设计。

---

## 1. V1 核心判断

V1 不继续扩展角色资产，不新增其他星灵视频，不把 10 星灵做成 10 套可视陪伴者。

Garden-Spirit V1 的情感锚点是：

```text
月灵是唯一可见陪伴者。
星灵在花园等你，今天带你看那一道星光。
```

产品目标不是让用户感到“系统功能很多”，而是让用户感到：

```text
这里很安静。
它知道我在说什么。
重要的东西会被花园收好。
我愿意明天再回来。
```

## 2. 月灵与星曜视角

### 2.1 唯一可见陪伴者

V1 全站可视陪伴者固定为月灵：

- 首页主视觉固定月灵动态视频。
- Chat 顶部陪伴者固定月灵。
- 信箱、宇宙、回访引导的主叙事由月灵承担。
- 不新增太阳、金星、土星等独立视频 / 独立场景 / 独立主视觉资产。

### 2.2 其他星曜的定位

其他星曜不是 V1 的独立角色资产，而是月灵请来的“星光视角”。

可出现的位置：

- 证据链中的行星 / 宫位线索。
- 信件落款的星曜印章。
- 主题观星台的视角提示。
- 自我星盘轮中的内在镜头。
- 折叠脚注、色彩、符号、徽标。

不可出现的方式：

- 不替换月灵成为主陪伴者。
- 不在前端凭入口主题硬编码“事业=土星”“关系=金星”。
- 不让用户感觉进入 Chat 后换了一个陪伴对象。

### 2.3 推荐话术

当后端证据链提供明确星曜视角时：

```text
这一次，我想陪你借土星的视角看看：你承担的责任，是不是已经超过了自己的边界。
```

当后端尚未提供明确星曜字段时：

```text
这一次，我们换一个角度慢慢看。
```

不要前端自行猜测星曜。

### 2.4 未来契约预留

未来可在后端输出中预留：

```json
{
  "visible_companion": "moon",
  "perspective_planets": ["saturn", "venus"]
}
```

规则：

- `visible_companion` 是 UI / 品牌层字段。
- `perspective_planets` 必须来自 Domain / EvidenceChain / Report，不来自前端猜测或 LLM 自由发挥。

## 3. 序章与首页口径

### 3.1 序章保持世界观介绍

序章当前承担的是“告诉用户星灵花园是做什么的”。这个方向保持，不因 V1 产品收口而改成短促转化页。

序章重点：

- 星灵花园是什么。
- 星图为什么与用户有关。
- 用户可以问问题，也可以只是倾诉。
- 花园会听见并记住重要时刻。

### 3.2 首页核心问题从“谁”改为“看什么”

旧口径：

```text
今天谁来陪我？
```

V1 新口径：

```text
今天，月灵陪我看见什么？
```

品牌句：

```text
星灵在花园等你，今天带你看那一道星光。
```

首页不是报告货架，不是数据 Dashboard，也不是多角色选择页。

### 3.3 首页第一句话

首页进入正式花园后，月灵第一句话应优先承接用户状态，而不是解释功能。

优先级：

1. 有 `continue_from`：承接昨天未说完的主题。
2. 有今日未读来信：轻提醒。
3. 有待验证判断：温柔邀请校准。
4. 有今日碎片：提示某个内在角落正在发光。
5. 无历史：给低压力开场。

示例：

```text
你回来了。昨天那句话，还可以慢慢说。
```

```text
今天这道星光，像是在提醒你先别急着证明什么。
```

```text
如果不知道从哪开始，就只说：我今天有一点迷茫。
```

## 4. Chat 闭环：从逐轮结算改为低打扰沉淀

### 4.1 当前问题

逐轮出现完整闭环卡会打断聊天情绪。尤其用户刚说完难过、困惑或关系问题时，立即出现“点亮 / 来信 / 报告 / 去信箱”等系统结算，会让陪伴感变成工具感。

### 4.2 V1 原则

Chat 中默认不展示完整闭环卡。

闭环反馈分三级：

1. **无打扰**：普通轮次不展示任何结算。
2. **轻提示**：重要沉淀发生时，只短暂显示一句。
3. **会话级聚合**：用户离开、主动查看或回首页时，再汇总本次谈话留下的星光。

### 4.3 轻提示文案

可选文案：

```text
✦ 花园替你收好了一点星光
```

```text
✦ 这句话被月灵轻轻记下了
```

```text
✦ 有一个内在角落，刚刚亮了一下
```

规则：

- 不展示复杂操作按钮。
- 不展示多张卡片。
- 不强迫用户跳信箱或宇宙。
- 不在每轮重复出现。

### 4.4 会话级聚合

聚合展示发生在：

- 用户主动点击“本次星光”。
- 用户离开 Chat 前。
- 回到首页后的轻量提示。
- 当日第一次进入信箱或宇宙页。

聚合内容示例：

```text
这段谈话，花园替你收好了：

· 一个关于边界感的内在角落亮了一下
· “害怕让人失望”这件事被月灵记住了
· 你提到的那个小行动，已经进入成长账本
```

### 4.5 验收标准

- 连续聊天 10 轮，不出现 10 张闭环卡。
- 同一会话最多出现一次完整聚合总结。
- 没有重要沉淀时，不展示任何结算 UI。
- 用户可以主动查看沉淀，但不会被系统打断。
- 报告入口不在普通轮次强行出现。

## 5. 记忆体系三层分离

V1 必须区分：

```text
结构化记忆 ≠ 灵魂碎片 ≠ 记忆来信
```

### 5.1 结构化记忆

用途：让系统以后更懂用户。

例子：

- 用户最近正在考虑换工作。
- 用户与母亲关系影响事业选择。
- 用户确认自己害怕冲突。
- 用户完成了之前说过的行动。

规则：

- 可以高频写入。
- 默认不可见或弱可见。
- 不等于生成来信。

### 5.2 灵魂碎片 / 成长账本

用途：记录用户被照见和行动复利。

例子：

- 边界感被点亮。
- 被理解需求被照见。
- 实际行动触发成长分。

规则：

- 可中频发生。
- 进入自我星盘轮 / 宇宙页 / 成长趋势。
- 不自动拆成多封信。

### 5.3 记忆来信

用途：保存真正值得回看的时刻。

规则：

- 低频。
- 稀缺。
- 聚合。
- 有主题。
- 有纪念感。
- 不是聊天回复原样复制。

记忆来信不是“系统写回成功提示”，而是“这段体验值得留下”的纪念物。

---

## 6. 记忆来信触发规则

### 6.1 允许生成的场景

V1 记忆来信只在以下场景生成：

1. 用户主动点击“把这段话收成一封信”。
2. 一次深聊形成完整主题闭环。
3. 用户说出明确且重要的新自我认识。
4. 用户完成此前反复提到的实际行动。
5. 每日 / 每周从多个碎片中整理出阶段来信。

### 6.2 不应生成的场景

以下场景不自动生成来信：

- 普通寒暄。
- 单轮短问答。
- 每次情绪低落。
- 每次 `needs_care`。
- 每次点亮碎片。
- 每次写入结构化记忆。
- 每条助手回复后。

### 6.3 频控规则

推荐 V1 频控：

- 同一会话自动记忆来信最多 0–1 封。
- 同一天自动记忆来信最多 1 封。
- 用户主动收藏可以突破自动频控，但仍应合并同一会话内容。
- 多个碎片先进入账本，不拆成多封信。

### 6.4 来信内容规则

记忆来信应当是整理后的纪念物，不是聊天流水账。

必须避免：

- 原样复制助手回答。
- 把每个碎片写成一封信。
- 把脚注、推导链和正文混在一起。
- 用系统口吻说“本次点亮了 N 个碎片”。

推荐结构：

```text
标题：一句疗愈名 / 主题名
正文：围绕一个主题整理后的来信
脚注：本次相关灵魂碎片
星光视角：由后端证据链授权的行星 / 宫位线索
推导链：默认折叠
```

### 6.5 验收标准

- 连续聊天 10 轮，自动来信最多 0–1 封。
- 普通寒暄和短问答不生成来信。
- 点亮多个碎片时，不拆成多封信。
- 用户主动收藏时，生成一封聚合信。
- 信箱增长慢，但每封信都值得重新打开。

## 7. 信箱：少而重要

### 7.1 信箱定位

信箱不是消息流，不追求数量。

信箱核心感觉：

```text
花园替我保存了重要时刻。
```

### 7.2 首页 / 信箱露出优先级

首页只露出少量重要资产：

1. 今日来信 / 今日日推。
2. 最近一封真正有重量的记忆信。
3. 一个最近值得回看的碎片。
4. 待验证判断入口。

不要把所有资产堆成消息列表。

### 7.3 来信与碎片关系

- 碎片可以每日沉淀。
- 来信只在重要时刻生成。
- 来信详情中可引用相关碎片作为脚注。
- 信箱列表不展示碎片流水账。

## 8. 与技术线的边界

### 8.1 技术线可继续独占的范围

当前若另一个 Agent 正在推进 V8 技术线，本产品线暂不直接修改以下共享代码：

- `frontend/src/pages/universe/consult.vue`
- `frontend/src/pages/chat/chat.vue`
- `frontend/src/api/client.ts`
- `/chat` 请求结构与 SessionContext
- IntentParser / ReportRequest / EntryContext
- report-intent 相关测试

### 8.2 产品线当前可安全推进的范围

- 产品契约文档。
- V8 / roadmap 文档口径同步。
- 验收标准冻结。
- 后续代码改动清单设计。

### 8.3 技术线完成后的产品线实施顺序

技术线合并后，再按以下顺序改代码：

1. 固定月灵为唯一可见陪伴者。
2. Chat 闭环卡降噪。
3. Keepsake / 记忆来信触发策略重构。
4. 会话级沉淀聚合。
5. 首页品牌文案更新。
6. 信箱“少而重要”呈现调整。
7. 回归测试与手动冒烟。

## 9. V1 上线前产品验收

### 9.1 身份一致性

- 首页看到的是月灵。
- Chat 看到的是月灵。
- 信箱主叙事来自月灵。
- 其他星曜以视角 / 印章 / 证据出现，不替换月灵。

### 9.2 低打扰体验

- 连续聊天不会被频繁结算卡打断。
- 用户能沉浸说话，而不是不断被引导跳页面。
- 沉淀反馈可主动查看。

### 9.3 记忆资产质量

- 信箱不是流水账。
- 来信数量不膨胀。
- 每封记忆来信都有主题和纪念感。
- 碎片与来信不混淆。

### 9.4 技术边界

- 前端不硬编码占星结论。
- 前端不硬编码事业=土星、关系=金星等星曜视角。
- LLM 不决定行星权威、吉凶、宫位、征象星、时机权威。
- 星曜视角必须来自后端契约或以中性“换个角度”表达。

## 10. 推荐更新到其他文档的口径

### 10.1 `frontend_ia_uiux_v8.md`

需要同步：

- 首页职责从“今天谁来陪我”改为“今天月灵陪我看哪一道星光”。
- Chat 闭环从“气泡下方闭环卡”改为“低打扰轻提示 + 会话级聚合”。
- 信箱增加“记忆来信低频稀缺”的规则。
- 其他星曜定位为“星光视角”，不是 V1 可视陪伴者。

### 10.2 `roadmap_v1.md`

需要同步：

- C1 “富字段反馈”不再定义为逐轮可见结算卡。
- keepsake_created 不再直接等于“星灵为你写了一封信”的强提示。
- 新增 V1 产品 P0：月灵身份统一、闭环降噪、来信稀缺化。

### 10.3 `product_report_uiux.md`

需要同步：

- “十大星灵人格”在 V1 中不等于十个可视角色。
- 月灵为门面 IP；其他星曜为视角层。
- 记忆来信是资产，不是每轮写回的 UI 包装。
